## 2. 历史系统组成

```text
Windows 工作电脑 → SSH/SCP → 机器人服务器（Orin NX，Ubuntu，ARM64）
  机器人服务器 → SDK2 / DDS → G1 身体 29 关节
              → FTDI 多路 USB 串口 / 电机 SDK → 左、右 Dex1-1
              → USB / RealSense SDK → 头部 RGB-D
              → USB / V4L2 → 左、右腕部图像
```

身体与夹爪是两条控制通道，但规划中必须作为同一机械装配建模。夹爪不属于身体 `LowCmd` 的 29 个关节；夹爪随手腕运动，其导轨和夹指又随开合改变空间。

历史实验主要改变右臂七关节，身体控制器仍向全部 29 关节发送保持或运动命令。其他关节不动不等于无力矩、无发热。左右夹爪不能套用同一零点、角度方向或行程。

## 5. 身体接口与关节映射

历史实测主题为 `rt/lowstate` 和 `rt/lowcmd`，消息为 `unitree_hg::msg::dds_::LowState_ / LowCmd_`。反馈包括 `q/dq/tau_est/motorstate/temperature`、CRC与模式；命令包括关节 `mode/q/dq/tau/kp/kd` 及CRC。单位分别为 rad、rad/s、Nm，`tau_est` 不是已标定末端力传感器。

| 索引 | 关节次序 |
|---|---|
| 0–5 左腿 | 髋俯仰、髋侧摆、髋偏航、膝、踝俯仰、踝侧摆 |
| 6–11 右腿 | 同上 |
| 12–14 腰 | 偏航、侧摆、俯仰 |
| 15–21 左臂 | 肩俯仰、肩侧摆、肩偏航、肘、腕滚转、腕俯仰、腕偏航 |
| 22–28 右臂 | 同上；正式名称为 `right_*_joint`，肘为 `right_elbow_joint` |

历史 `mode_machine=5, mode_pr=0` 只是采样值，不能单凭它断言当前FSM或谁在保持。`rt/arm_sdk` 与 `rt/armsdk` 曾呈现不同端点，不应混写为同一接口。上层试探当时未形成预期运动，不代表所有模式都不可用。

历史身体发布目标频率约500 Hz（2 ms），不是已证明的硬实时保证，也不等于日志和图像频率。位置模式仍发送增益与前馈；不能只比较目标角度判断两个控制器是否等价。关节工作范围、增益、速度、反馈误差与温度门限必须审查本次实际控制器，不能从历史表自动套用。

控制项可用下式理解，电机内部限制与实际响应仍需核对：

```text
tau_command ≈ tau_ff + Kp × (q_des − q) + Kd × (dq_des − dq)

历史静态保持力矩转移：
q_des_new = q_measured
tau_ff_new = tau_ff_old + Kp × (q_des_old − q_measured)
```

历史位置插值中发送的目标速度为零，不是轨迹导数前馈。静态转移仅在相应采样状态、增益和速度等项匹配时保持采样点总指令力矩连续，不能代替完整重力模型或消除未知接触。积分补偿曾改善有限且增加发热，后来禁用；不能因旧文件、重启或交接重新叠加。

## 6. Dex1-1 设备身份、单位与副作用

| 项目 | 历史实测／枚举 | 本次要求 |
|---|---|---|
| 转换器 | FTDI FT4232H，序列号 `DEVICE_ID_02`，VID:PID `0403:6011` | 核对当前序列号与接线 |
| 右夹爪 | interface01 → `ttyUSB1`，电机ID 0 | 不依赖节点编号；重新确认侧别 |
| 左夹爪 | interface02 → `ttyUSB2`，电机ID 1 | 方向、零点未完成标定；不能套右侧 |
| 稳定路径格式 | `/dev/serial/by-id/DEVICE_TO_CONFIGURE` | 右侧历史为if01，左侧为if02；核对软链接目标 |
| 电机配置 | `MotorType::M4010`，6 Mbps，SDK减速比25 | 核对实际SDK和设备；4 Mbps曾失败 |
| 权限 | 曾需临时 ACL；重启失效 | 区分权限、占用、超时、无效回包与设备离线 |

令减速比为 `g`：`q_output=q_motor/g`，`dq_output=dq_motor/g`，`tau_output=tau_motor*g`；指令反向换算，输出侧Kp/Kd到电机侧除以`g²`。显式初始化全部命令字段，并用当前SDK定义验证换算。输出角度不是毫米开口，估计力矩不是牛顿夹持力。

SDK串口构造曾不接受 by-id 软链接名称，解析成实际节点后可用；启动初次读取曾无效，初始化等待及有界重试后恢复。只重试有依据的通信步骤，不持续机械试探。未收到有效回包的温度或位置不得当作实测值。

`gripper_probe` 会发 BRAKE，`gripper_guard` 启动即保持；两者都不是纯被动查询。历史Kp=5、Kd=0.05及力矩/位置夹限只属于特定实验配置，未建立任意物体通用夹持参数。`contact=true` 不能证明承载或抗滑。

厂家串口转DDS服务使用独立主题 `rt/dex1/right/cmd`、`rt/dex1/right/state` 与左侧对应主题，消息层为 `unitree_go` 的 `MotorCmds_/MotorStates_`；不能与身体 `unitree_hg::LowCmd_` 或电机SDK的 `MotorCmd` 混用。本机历史直接控制串口，没有运行该桥接；本次需核对实现和占用。[厂家服务说明](https://github.com/unitreerobotics/dex1_1_service)

| 相机 | 历史标识 | 重要限制 |
|---|---|---|
| 头部 D435i | 序列号 `DEVICE_ID_01` | 用RealSense SDK按序列号选择，不能按video号猜RGB/深度 |

腕部历史by-id格式：`/dev/v4l/by-id/usb-DEVICE_ID_03_DEVICE_ID_03_DEVICE_ID_03-video-index0`，右侧替换为DEVICE_ID_04。启动视频采集可能与其他程序争用设备，但不发送身体电机命令。

保留16位原始深度；零深度为无效，不用可视化图代替测量，不重复乘尺度。透明瓶、反光、细夹指边缘和遮挡需要筛选。三台相机没有完成严格同步；顺序快照与前后状态文件不是同一曝光时刻。

## 8. 控制权、温度与每次必须读取的状态

查询占用、`ReleaseMode`、位置保持、停止发布、渐退输出、切换站立模式均不同。曾在释放原占用后停止lowcmd导致手臂下垂；更新控制器要验证命令、增益及总力矩连续性。文件锁只能约束遵守它的程序，不证明没有其他控制源。

历史 `dex1_gripper.service` 为inactive/disabled且指向不存在的旧目录，不能直接启动；当前服务状态、ExecStart、串口占用和DDS发布者都要重查。厂家Dex1服务可桥接夹爪DDS主题到串口，历史实验直接控制串口，不能同时运行两者。

身体SDK辅助函数默认壳体`temperature()[0]`为85℃、绕组`temperature()[1]`为120℃。这是软件判断默认值，未核实为固件动作门限，也不是建议持续工作温度；夹爪历史55℃为自建程序门限。低温起步、趋势、负载、剩余任务和撤回时间比单一未越限更重要。恢复要求见[03](03_执行流程与异常恢复.md)。

每次至少记录：boot/run ID、状态时间与新鲜度、模式与控制来源、CRC、29关节q/dq/估计力矩/故障/双温度、SOC及供电条件、夹爪状态与串口占用、相机身份、当前安装变化。未知G1铭牌/固件、电池规格、附件质量重心、电气针脚不得用宣传参数补齐。

可选历史证据位于旧工作区的 `G1机器人_硬件配置与接口参考.md`、`observations/hardware_inventory_2026-10-16.json`、三次实验复盘和`robot_tools/`。它们不随库搬迁也不影响阅读；实际执行所需SDK、工具和模型仍须另行验证取得。


## 9. 2026-10-21 双臂和空载夹爪验证补充

验证条件：调试模式、吊架完全承重，无其他运动控制来源。证据属于当次实验，不代表站立/行走条件或持物操作已经验证。

- 已实现并实测**单个身体发布器同时管理两臂**：一个 `unitree_hg::LowCmd_` 消息包含29关节；本轮主要改变15—28两臂目标，0—14保持起始反馈。两侧夹爪各用独立串口进程。旧左右单臂程序都能发送29关节，并不表示历史实验同时运行过两个发布器；以前主要是一次运行一个。
- 两臂约0.30/0.40 rad外展、自动返回及渐退退出已经空载验证。正方向使两侧夹爪张开；反方向闭合。左夹爪一次约4.6 rad往返、右夹爪约3.7 rad闭合后返回已实测。零点、毫米开口、牛顿夹持力仍未标定。
- 本轮原自设0.4/0.5 Nm输出侧比例力矩上限不能可靠完成左夹爪大行程；不能据此认定机构损坏或已经接触物体。保持速度上限0.25 rad/s、实测力矩保护1 Nm，通过单次小行程辨识后，输出侧比例上限0.8 Nm、Kd=3、外层比例斜率3、SDK输出侧Kp=5完成空载大行程。它们是本轮空载参数，**没有证明夹瓶或拧盖所需力，也不能自动套用在接触阶段**。
- SDK DDS收尾出现过析构断言和后续队列回调段错误。当前局部实现采用 `CreateRecvChannel(...,0)` 同步回调、主线程保留原生reader强引用并显式close；被动观察器在gdb下连续5次正常退出，随后有限运动程序也正常退出。只说明这些版本及测试范围通过，不是所有并发/异常均已解决。
- `task_observe_fixed` 为本轮只读观察器；`bimanual_finite_profile`、`bimanual_finite_servo`、`bimanual_finite_waist` 是有限空载运动工具，不是现成拧盖任务入口。`cap_task_body.cpp` 是未完成接触控制原型，现已在启动DDS之前拒绝 `--execute`，不得把编译成功当作可执行任务。

本轮RealSense SDK报告序列号254322075469，而UVC/by-id历史标识为DEVICE_ID_01；差异原因未确认，不静默改写为同一已验证身份。每次从当前SDK枚举并核对真实画面。`dex1_gripper.service` 当次反复启动失败，MainPID=0、状态200/CHDIR；没有修改该服务或厂家文件。
