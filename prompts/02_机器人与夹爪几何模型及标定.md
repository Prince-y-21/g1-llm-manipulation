# 02 机器人与夹爪几何模型及标定

库版本：`2026-10-21.2`。适用对象：本机G1、Dex1-1、三相机及任务环境。本文定义需要建立和验证的几何能力，不宣称这些工作已经完成。接口见[01](01_本机硬件与控制接口.md)，动作编排见[03](03_执行流程与异常恢复.md)。

## 1. 当前能力与缺口

| 内容 | 截至2026-10-20的证据状态 | 不能据此声称什么 |
|---|---|---|
| 身体反馈 | 历史能读取全部29关节 | 不能等同于全身碰撞建模完整 |
| 身体运动学 | 从G1 URDF提取右臂/左臂；后补腿链 | 不代表全部link、碰撞体、网格均被实际检查 |
| 初期碰撞模型 | 手臂采样、躯干/头部简化包络、桌面及物体 | 初次展开遗漏腿部，是运动前检查缺口 |
| 后期腿部模型 | 按某次q及腰角生成腿部点与胶囊 | 不是每周期由实时全身反馈更新的统一模型 |

| 携物模型 | 近似瓶形与接触时相对注册 | 未证明抗滑；滑移会使固定注册失效 |

## 2. 装配关系必须统一

身体与Dex1可以由不同进程、协议和频率控制，但碰撞规划必须使用同一装配关系：

```text
世界/任务参考 → pelvis → 腰 → torso → 肩 → 肘 → 腕
                                              → 安装座/转接件
                                              → 夹爪固定本体
                                              → 随开度移动的夹指与导轨
                                              → 腕部相机、线缆等附件
                                              → 携带物（承载验证通过后）
```

每条变换明确父子坐标系、单位、轴方向、变换方向、来源和误差。记录是否依赖关节q、夹爪开度、腰姿态或时间。矩阵书写建议用`T_parent_child`表示把child坐标变换到parent，不能凭文件名猜方向。

承载验证前仍需按带不确定性余量的假设载荷检查试提和回落，不能因为尚未证明抓稳就忽略瓶子几何；此时不能把注册关系称为已验证刚性连接。

关节角可推算看不见的连杆姿态，不意味着能看见所有附件。吊带、线缆、改装支架、外壳变形、安装松动和关节零点偏差需要独立核对。腿不执行任务也仍是障碍物；全身目标保持不消除静差或身体相对桌面的移动。

## 3. G1基础模型与实际末端差异

历史文件为`g1_29dof_rev_1_0.urdf`，SHA-256为`C0AE739C640C3E2C00D1BDD8810B5D6E59601487BD1A3995859F9543269EE5C8`。该哈希只标识历史文件，不证明它与本机实物完全一致。官方模型线索为[unitree_ros中的G1模型](https://github.com/unitreerobotics/unitree_ros/blob/master/robots/g1_description/g1_29dof_rev_1_0.urdf)。

这个URDF末端是`left_rubber_hand/right_rubber_hand`，不是实物Dex1。原掌固定关节的平移为左`(0.0415,0.003,0)m`、右`(0.0415,-0.003,0)m`。不能直接用橡胶手碰撞体、质量、重心或掌坐标作为Dex1 TCP。

应当保留原模型作为可追溯基础，另建装配版本替换末端并加入附件；不要静默改厂家文件。URDF内effort/velocity是模型字段，不能作为当前固件或持续运行许可。视觉网格存在不等于碰撞网格完整，引用网格缺失也不能被默默跳过。

若暂用胶囊、盒体等简化形状，要证明覆盖相关实物外形，并说明排除项和不确定度；未经验证的“保守”不能靠命名成立。模型清单应列出所有相关身体部件和碰撞对，不只列“已加载URDF”。

## 4. Dex1占用空间不能只看夹指间距

2026-10-20查阅的[Dex1-1官方参数及注释](https://www.unitree.com/cn/mobile/Dex1-1/)给出以下宽度。它们为厂家资料，尚未核对本机具体硬件版本和转接装配；网页也说明以实物为准。

| 厂家描述的状态 | 宽度 | 对规划的含义 |
|---|---:|---|
| 半张开对应最小宽度 | 78 mm | 不是任意状态通用外宽 |
| 全张开 | 120 mm | 开指会改变占用空间 |
| 全闭合两侧导轨伸出 | 124.5 mm | 指尖闭合并不表示整机更窄 |

以上三项不足以构成完整三维包络，也不能直接算作开口标定。不能据此套一个未确认安装方向的124.5mm盒体就宣布模型完成。

历史代码用过手腕前约190mm的参考点、延伸到225mm的工具采样；另按“空手／携物／闭合空手”切换横向参数。这些是近似，未证明覆盖导轨、底座、相机、接头等。尤其较窄的闭合分支必须重新审查，不能继续默认有效。

需要建模并实测核对：安装座与转接件、固定壳体、电机突出部、夹指形状、导轨随开度位置、腕相机及支架、插头与线缆允许活动区。质量/重心与几何尺寸分开记录，不能由能避障推断负载补偿正确。

至少用闭合、中间和张开状态比较模型与多方向实物照片/测量，并检查整个开合过程的扫掠空间；考虑开合方向、左右侧差异、回差和角度零点。角度到开口毫米和角度到外包络需要分别验证。

## 5. 相机标定：哪些已有，哪些仍需验证

深度相机内部参数把像素和深度转换到相机坐标；相机安装到机器人后，还需要准确的外部变换。厂家内部标定不能自动给出本机支架、手腕和夹持点的实际关系。没有必要无依据重做所有内参，但必须检查当前流和标定状态。

| 项目 | 作用 | 历史状态／应补验证 |
|---|---|---|
| RGB/深度内参、畸变、尺度及对齐 | 像素到相机三维位置 | 设备曾可读；每次当前流读取，必要时检测精度 |
| 头相机到torso | 物体相机坐标到机械臂参考系 | 采用URDF安装近似，实物未充分标定 |
| 腕相机到手腕 | 随手运动的图像定位、视觉伺服 | 手眼关系未知；安装后需估计与独立验证 |
| 手腕到TCP/夹持面 | 手腕目标转为有效夹持位置 | 约190mm经验值不是完成标定 |
| 夹爪角度到开口/外形 | 控制目标与夹持尺寸、碰撞体 | 未完成，左侧尤其不能套右侧 |
| 机器人到桌面/任务参考 | 把环境与身体统一 | 每次场景读取，承重或腰角变化后更新 |
| 时间关系 | 图像、关节、夹爪姿态对应 | 未完成严格多设备同步，不能按文件名视为同步 |

标定可由程序辅助甚至自动采集，不必要求用户手工测所有量。先核对厂家安装资料与实物是否一致；不一致或精度不足时，再选择标定板、已知几何或其他可验证方法。用户只承担确实需要的现场摆放和测量。

采集多个具有足够姿态变化、可见且不近似退化的位置；避免仅凭一张图或一个姿态拟合所有关系。用没有参与求解的新姿态评估误差，保留残差、重复性和最差情况，报告位置/角度误差及有效范围。标定运动也需要事先检查路径和热余量。

## 6. 坐标与动态场景的处理

历史控制采用躯干参考近似：X向前、Y向左、Z向上；右方通常为负Y。光学坐标通常X向图像右、Y向下、Z向前，但实际程序必须核对SDK和变换约定。毫米、米、度、弧度应显式转换。

历史头相机URDF平移`(0.0576235,0.01753,0.42987)m`、俯仰约0.830776724rad仅为模型线索；光学轴转换也需单独核对。不能将这些量直接写成已测外参。

桌面拟合残差约2mm只表示点云对该平面的局部残差，不能等同于整体定位2mm。透明瓶深度、外参、关节静差、时间差及吊挂身体移动可能使端到端误差更大。桌面、杯子、瓶子和身体应使用带时间戳的统一坐标关系。

悬挂承重、腰部保持力矩或增益变化后，旧场景坐标可能失效；根据实测响应刷新。不要把躯干固定当成实验事实，也不要将初始桌面坐标无期限当成世界参考。

## 7. 运动前模型与路径检查完成条件

- 明确本次实际q、夹爪状态和场景时间，并覆盖运动相关的腿、腰、躯干、头、另一臂、工具和附件。
- 明确自碰撞对、环境碰撞对和允许接触对象；允许接触目标瓶不等于允许夹爪底座或导轨碰桌。
- 按当前开度的已验证几何，或覆盖允许开合全过程的已验证包络检查；不要求每次先建立精细开度映射。不同控制通道的状态要时间对应。
- 从真实起点到每个阶段检查整段路径，包含展开、接近、开合、携物、放置、空手退出与归位。
- 携物几何只有在承载验证后才可作为刚性附着；滑移、瓶体变形或抓持变化后重新注册或返回。
- 离散采样密度应与几何、运动幅度和余量匹配；端点通过、IK通过或81/101个采样点都不是连续无碰撞证明。
- 不确定度进入间距与动作幅度；不能通过缩小包络、删除障碍或提高门限让失败路径“通过”。
- 验证工具相对躯干、腿和桌沿的实物位置；先小幅确认坐标方向与响应，再逐渐扩大。

若初始近似包络已重叠，先区分模型误差与实物邻近，读取相机与反馈。正常路径规划失败时不能继续向重叠更深处运动；若需撤离，建立有证据的受限恢复，要求已有间距持续改善且不引入其他碰撞。不能把历史外撤角直接重放。

## 8. 维护成果与重验证触发条件

每个装配/标定版本至少保存：模型文件及网格清单、哈希、父子坐标、单位、关节/开度映射、覆盖与排除项、来源、误差、验证日期、姿态范围和证据。清单模板见[模型与配置目录](模型与配置/README.md)。文件齐全与“完成实物验证”是两个独立状态。

更换夹爪/相机/支架、调整安装、碰撞或松动、关节零点或固件变化、图像分辨率/裁切/对齐变化时重验证相关项。只改变任务物体，也要更新场景、抓持关系、负载及成功判据。
