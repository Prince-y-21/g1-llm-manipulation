## 3. 工作与沟通方式

1. 当前用户明确任务决定范围；既有授权内的准备、修复和阶段执行不反复请求批准。只有现场才能确定且影响执行的条件集中询问一次。
2. 对物体位置、场景和代码问题自行调查，区分已验证事实、有依据推断和待确认假设。未观测到位移不能说成严格零接触；模型残差不能说成实物精度。
3. 吊架承重、脚部承重、急停人员、其他控制来源必须属于本次有效确认；不能从旧实验继承。安装和摆放变化需要检查。
4. 复用没有失效的已验证资料，不每次全盘重新开发。重启、卸力、安装/模式/姿态/载荷变化后，按影响范围重新检查。
5. 简明报告进展、异常、证据和下一步。主要规划、编译与资料调查放在接管前或已验证低负载姿态，避免伸臂等待分析。
6. 从任务开始记录 token 用量基线，结束记录同一统计范围的增量；列明起止、采样时间、会话/代理 ID、来源及缺失范围。按主代理与子代理去重，分叉继承历史不能重复计入。详见执行文档的 token 记录规则；无法读取就标未知，不用额度百分比、字数估算或折算费用。

| 统一几何与感知 | 真实末端替换 rubber_hand，腿部及相关身体/附件/环境纳入，坐标与时间对应，误差和缺口明确 |
| 路线与恢复 | 从实际起点检查展开、开合、接近、携物、放置、回程，以及超时/温升/失败时的可用分支 |
| 平滑接管与验证 | 目标、增益、前馈和阶段连续；小幅核对方向与实际响应，再扩大动作 |
| 物理效果与收尾 | 接触、承载、搬运/倾倒和支撑放置分别验证；按约定保持、交接、暂停或退出并核验 |

## 5. 不得省略的几何与抓持要求

- 读取 29 关节或加载 URDF 不等于完成全身碰撞检查。静止的双腿、另一臂等仍是障碍；腰腿反馈变化后刷新相关几何，不让静态文件冒充实时模型。
- G1 基础 URDF 曾带 rubber_hand；实际 Dex1-1、转接件、腕部相机、本体、导轨、夹指和相关线缆必须整合进装配链。
- TCP 是参考点，不能代表占用体积。夹指闭合不代表整个夹爪更窄；导轨可能外伸。使用经验证的开度几何或覆盖允许开合全过程的包络，不为通过检查而缩小模型。
- 简化几何需要覆盖依据；路径检查包括实际/命令起点、过程和允许误差。IK 成功、端点通过或固定采样点数不保证实物路径安全。
- 允许接触只针对明确阶段、区域和碰撞对，例如夹指与目标、瓶底与支撑面；不能全局关闭目标或其他身体碰撞检查。
- 开口角度不是毫米，估计电机力矩不是指尖夹持力。左右零点和方向分别确认，不强推未核对端点。
- contact 可能是锁存事件，不能单独证明当前承载。按“接触→初步夹持→小幅试提→承载通过→携物”推进；联合真实手臂响应、外部离桌/随手移动、腕图相对稳定和夹爪反馈。
- 支撑状态的载荷配准只是临时假设。试提前按不确定性载荷检查路径，承载通过后才能作为稳定刚体使用，滑移后立即失效。

## 6. 控制、温度和编排的核心约束

**用户指定的阈值规则：** 关节角度、速度、力矩、温度等上限采用与本机型号和配置相符的宇树官方最大值，并按官方原有适用条件使用。不额外设置更低的自定义上限，不另设自定义跟踪误差停机门限；官方未明确的数值不自行编造。历史脚本中的自设门限不得作为新任务默认值。

- 查询、ReleaseMode、保持、停发和切换模式各不相同。明确谁在保持后再接管，不擅自切换站立/行走；悬挂底层保持不能替代平衡控制。
- 身体发布器和夹爪串口分别互斥；文件锁与 CRC 监测不等于所有控制来源已被认证。程序更新采用已验证交接，不能先杀旧进程再猜测姿态会保持。
- 检查 q、dq、Kp/Kd、前馈及总指令力矩。历史静态力矩转移只在对应采样点匹配控制项时连续，不是全姿态重力模型；遗留积分补偿不能重启叠加。
- SDK 壳体 85℃/绕组 120℃为软件辅助默认判断，非已核实固件门限、非建议长期工作温度。任务需提前减载余量、冷却条件和电量预算，不靠抬门限继续。
- 故障冻结目标仍可能保留力矩发热。任务监督要覆盖计算、相机和子进程等待；SSH 断开或上层停止也不意味着服务器底层控制器停止。
- 临时跳过温度拒绝的历史热卸载版本不作常规入口。故障不能简单清标志、重启或加力重试；使用预先准备的受约束恢复，条件不足时说明所需现场协助。
- 每次新 task/run 隔离旧目标、请求与退出标记。依赖步骤失败就停止，绑定模型/场景/路线版本，避免失败后执行残留 ready 文件。
- 分别确认规划、发送、正确序号被接受、执行完成和物理效果。旧 moving=false、文件写入或序号增加均不等于新动作完成。

## 7. 暂停、退出与结果报告

普通暂停先停止推进新阶段，按预案保持、减载或支撑放置，报告仍运行的控制器及有界等待策略。停止控制/退出按本次约定完成最小必要处理，核验自己启动的程序退出，不擅自恢复别的服务。明确急停按现有急停与现场处置流程响应，不能以归位为由继续原任务。

物体悬空时不直接切断控制；退出方案在动作前确定。休息位、初始角度归位、卸力后自然姿态不是同一状态。停止后查看真实进程、串口、发布活动和被动反馈，不能把旧 status/PID 文件当在线状态；下一轮从新的实际姿态开始。

默认把文档和选取证据保存到本地，部署与服务器日志路径单独说明；不默认同步文档到机器人。记录请求、执行、验证、异常和恢复，不覆盖失败证据。训练任务另需连续同步采集，历史目标 500 Hz 与低频日志/快照不能混为完整训练轨迹。

最终说明：完成什么、用什么验证，物体和机器人结束状态，哪些程序仍运行，未解决问题，本地/服务器文件及时间统计口径。同时交付 token 统计范围、来源与已知增量：`total=input+output`，`cached_input` 是 input 子集、`reasoning_output` 是 output 子集，不能再次相加。当前回复或其他进行中调用尚未入账时明确截点；缺值保持未知。尚未倒水就明确未倒水，不将接触、规划成功或倾角当任务成功。

有新证据时，将可复用事实、失效结论和新增缺口更新到对应功能资料及状态清单，并记录来源、日期、版本和适用范围，再重新生成与校验导出。当前温度、姿态、PID 等只存本次run，不回填为长期事实；没有证据就不把未知改为已验证。若只拿到单文件或没有资料库写入条件，交付明确的待维护条目，不另造分叉维护源。

## 2. 历史系统组成

```text
Windows 工作电脑 → SSH/SCP → 机器人服务器（Orin NX，Ubuntu，ARM64）
  机器人服务器 → SDK2 / DDS → G1 身体 29 关节
              → FTDI 多路 USB 串口 / 电机 SDK → 左、右 Dex1-1
              → USB / RealSense SDK → 头部 RGB-D
              → USB / V4L2 → 左、右腕部图像
```

身体与夹爪是两条控制通道，但规划中必须作为同一机械装配建模。夹爪不属于身体 `LowCmd` 的 29 个关节；夹爪随手腕运动，其导轨和夹指又随开合改变空间。

历史实验主要改变右臂七关节，身体控制器仍向全部 29 关节发送保持或运动命令。其他关节不动不等于无力矩、无发热。左右夹爪不能套用同一零点、角度方向或行程。

## 3. 连接、主机身份与启动检查

```text
tau_command ≈ tau_ff + Kp × (q_des − q) + Kd × (dq_des − dq)

历史静态保持力矩转移：
q_des_new = q_measured
tau_ff_new = tau_ff_old + Kp × (q_des_old − q_measured)
```

历史位置插值中发送的目标速度为零，不是轨迹导数前馈。静态转移仅在相应采样状态、增益和速度等项匹配时保持采样点总指令力矩连续，不能代替完整重力模型或消除未知接触。积分补偿曾改善有限且增加发热，后来禁用；不能因旧文件、重启或交接重新叠加。

## 2. 装配关系必须统一

身体与Dex1可以由不同进程、协议和频率控制，但碰撞规划必须使用同一装配关系：

```text
世界/任务参考 → pelvis → 腰 → torso → 肩 → 肘 → 腕
                                              → 安装座/转接件
                                              → 夹爪固定本体
                                              → 随开度移动的夹指与导轨
                                              → 腕部相机、线缆等附件
                                              → 携带物（承载验证通过后）
```

每条变换明确父子坐标系、单位、轴方向、变换方向、来源和误差。记录是否依赖关节q、夹爪开度、腰姿态或时间。矩阵书写建议用`T_parent_child`表示把child坐标变换到parent，不能凭文件名猜方向。

承载验证前仍需按带不确定性余量的假设载荷检查试提和回落，不能因为尚未证明抓稳就忽略瓶子几何；此时不能把注册关系称为已验证刚性连接。

关节角可推算看不见的连杆姿态，不意味着能看见所有附件。吊带、线缆、改装支架、外壳变形、安装松动和关节零点偏差需要独立核对。腿不执行任务也仍是障碍物；全身目标保持不消除静差或身体相对桌面的移动。

## 4. Dex1占用空间不能只看夹指间距

| 厂家描述的状态 | 宽度 | 对规划的含义 |
|---|---:|---|
| 半张开对应最小宽度 | 78 mm | 不是任意状态通用外宽 |
| 全张开 | 120 mm | 开指会改变占用空间 |
| 全闭合两侧导轨伸出 | 124.5 mm | 指尖闭合并不表示整机更窄 |

以上三项不足以构成完整三维包络，也不能直接算作开口标定。不能据此套一个未确认安装方向的124.5mm盒体就宣布模型完成。

历史代码用过手腕前约190mm的参考点、延伸到225mm的工具采样；另按“空手／携物／闭合空手”切换横向参数。这些是近似，未证明覆盖导轨、底座、相机、接头等。尤其较窄的闭合分支必须重新审查，不能继续默认有效。

需要建模并实测核对：安装座与转接件、固定壳体、电机突出部、夹指形状、导轨随开度位置、腕相机及支架、插头与线缆允许活动区。质量/重心与几何尺寸分开记录，不能由能避障推断负载补偿正确。

至少用闭合、中间和张开状态比较模型与多方向实物照片/测量，并检查整个开合过程的扫掠空间；考虑开合方向、左右侧差异、回差和角度零点。角度到开口毫米和角度到外包络需要分别验证。

## 5. 相机标定：哪些已有，哪些仍需验证

深度相机内部参数把像素和深度转换到相机坐标；相机安装到机器人后，还需要准确的外部变换。厂家内部标定不能自动给出本机支架、手腕和夹持点的实际关系。没有必要无依据重做所有内参，但必须检查当前流和标定状态。

| 项目 | 作用 | 历史状态／应补验证 |
|---|---|---|
| RGB/深度内参、畸变、尺度及对齐 | 像素到相机三维位置 | 设备曾可读；每次当前流读取，必要时检测精度 |
| 头相机到torso | 物体相机坐标到机械臂参考系 | 采用URDF安装近似，实物未充分标定 |
| 腕相机到手腕 | 随手运动的图像定位、视觉伺服 | 手眼关系未知；安装后需估计与独立验证 |
| 手腕到TCP/夹持面 | 手腕目标转为有效夹持位置 | 约190mm经验值不是完成标定 |
| 夹爪角度到开口/外形 | 控制目标与夹持尺寸、碰撞体 | 未完成，左侧尤其不能套右侧 |
| 机器人到桌面/任务参考 | 把环境与身体统一 | 每次场景读取，承重或腰角变化后更新 |
| 时间关系 | 图像、关节、夹爪姿态对应 | 未完成严格多设备同步，不能按文件名视为同步 |

标定可由程序辅助甚至自动采集，不必要求用户手工测所有量。先核对厂家安装资料与实物是否一致；不一致或精度不足时，再选择标定板、已知几何或其他可验证方法。用户只承担确实需要的现场摆放和测量。

采集多个具有足够姿态变化、可见且不近似退化的位置；避免仅凭一张图或一个姿态拟合所有关系。用没有参与求解的新姿态评估误差，保留残差、重复性和最差情况，报告位置/角度误差及有效范围。标定运动也需要事先检查路径和热余量。

## 6. 坐标与动态场景的处理

历史控制采用躯干参考近似：X向前、Y向左、Z向上；右方通常为负Y。光学坐标通常X向图像右、Y向下、Z向前，但实际程序必须核对SDK和变换约定。毫米、米、度、弧度应显式转换。

历史头相机URDF平移`(0.0576235,0.01753,0.42987)m`、俯仰约0.830776724rad仅为模型线索；光学轴转换也需单独核对。不能将这些量直接写成已测外参。

桌面拟合残差约2mm只表示点云对该平面的局部残差，不能等同于整体定位2mm。透明瓶深度、外参、关节静差、时间差及吊挂身体移动可能使端到端误差更大。桌面、杯子、瓶子和身体应使用带时间戳的统一坐标关系。

悬挂承重、腰部保持力矩或增益变化后，旧场景坐标可能失效；根据实测响应刷新。不要把躯干固定当成实验事实，也不要将初始桌面坐标无期限当成世界参考。

| 软件与结果 | 实际将调用的源码、二进制和配置版本；监督器、超时、成功判据与原始记录方式 |

这份摘要用于让判断可检查，不要求用户再次批准已经授权的每一步。能通过资料与传感器调查的问题自行解决，仅集中询问现场才能确认且确实影响执行的条件。

重启后重新检查临时目录、串口 ACL、设备节点和进程。历史上 `/tmp` 文件、临时 ACL 与控制进程均曾消失；SSH 连通不代表运动接口恢复。工具名称不能证明只读：夹爪 probe 可能发 BRAKE，guard 启动后可能保持，ReleaseMode 会改变控制占用。

## 2. 新任务隔离与失败阻断

1. 每轮建立独立 `task_id/run_id`，记录 boot ID、源码/二进制/配置哈希、设备身份、模型/标定/场景版本与初始状态。
2. 归档旧目标、ready、release/stop/pause 标记、PID、序号和状态；不删除仍在运行实例依赖的文件。审查所有硬编码目录，不能只换启动路径。
3. 规划结果绑定本轮 ID、起点及允许偏差、模型/场景/开度/载荷版本、路线哈希和有效期。任一不匹配就失效，不以“文件存在”替代本次成功。
4. 编译、逆解、视觉或规划失败时阻断依赖步骤；PowerShell 显式检查退出码，子进程错误须向任务层传播。历史曾因前步失败未中止而执行旧接近段。
5. 干运行、候选规划、实际发送、接受、执行和物理验证分开记录；原始失败证据不被重算覆盖。旧绝对关节目标不能直接重放。
6. 同步建立 token 记录范围与起始基线，标明任务/会话/代理 ID 和采样截点；具体规则见第 10 节。不要为统计 token 延长高负载保持。

## 3. 控制接管与执行状态机

建议按下列状态推进；每个箭头都需要对应证据，状态名称不强制约束实现语言：

```text
只读核查 → 准备完成 → 连续接管 → 低负载就绪
→ 空手展开/开合 → 接近 → 接触候选 → 支撑附近试提
→ 承载已验证 → 搬运/任务动作 → 支撑放置 → 松开并独立稳定
→ 空手撤回/约定归位 → 约定保持、交接或退出 → 结束核验
任一阶段异常 → 对应恢复状态；不能直接跳回“成功”或复用旧目标
```

- 模式以本次约定为准，不擅自切换站立/行走。吊架承重下的全身位置保持不能替代未验证的平衡控制。
- 查询模式、ReleaseMode、位置保持、停止发布分别处理。必须先知道停止当前来源后谁维持姿态；历史释放占用后停发导致手臂下垂。
- 接管时目标贴合实时状态，同时核对 q/dq 参考、Kp/Kd、前馈与总指令力矩；仅 q 一致不保证输出连续。
- 身体和夹爪通道独立，但使用统一的任务阶段、时间信息、实际开度和载荷状态。不并发身体控制器，不并发占用同一串口。
- 程序更新先准备新版本，再验证继承目标、增益、前馈、阶段和序号，完成互斥交接。文件锁只约束遵循该锁的程序，不能当作控制权认证。
- 其他关节即使目标不变也可能出力、漂移与发热；必须纳入全身状态及温度检查。

## 4. 分段运动与接触规则

每段依次执行：读取新鲜状态 → 核对阶段/版本/控制权 → 从实际状态及当前命令参考检查路径 → 有界发送 → 等待本序号接受与结束 → 验证实际效果 → 决定下一段。

目标完整写入后原子替换，序号唯一。`moving=false` 必须对应刚发送目标的 `accepted_seq`，不能读到上一次的空闲状态就继续。检查实际位移、误差、速度、模式、故障与物体效果，留浮点裕量；序号增加或文件写入成功不代表实物执行成功。

| 阶段 | 可允许的接触示例 | 仍须检查 |
|---|---|---|
| 接近与开合 | 未指定时不允许新增接触 | 夹爪本体、导轨、指根、相机、腿、桌沿及其他物体 |
| 闭合 | 指定有效夹指区域与目标物 | 接触深度、变形、单侧顶推；不能全局忽略目标物 |
| 试提/携物 | 已定义的夹指—目标接触 | 假设载荷与真实瓶子、桌面、身体、杯子及环境 |
| 放置 | 目标物底部与指定支撑面 | 工具与桌面/桌沿、侧面碰杯、非目标物 |

允许接触必须指定阶段、碰撞对、区域和容差；开合全过程的扫掠空间也要检查。“闭合更窄”不适用于未核对的 Dex1-1 导轨。姿态、开度、物体、标定或载荷变化后，原检查可能失效。

若模型显示初始邻近/重叠，先核对实物、模型和误差；只有证据支持时才设计有界、逐步改善间距、无新增问题的撤离。不沿原任务推进，不缩小几何体让规划通过。跟踪误差不单独证明碰撞，模型重叠也不等于实测接触。

## 5. 接触候选、试提和真实承载

`contact=true` 可能来自机构阻力、瓶体变形、单侧接触或桌面支撑。历史实现中它在满足条件后锁存，滑移不会自动清零；需审查当前实现，不能把新鲜状态文件和持续 true 当作持续抓稳。

试提前先用带不确定性余量的假设载荷检查试提与回落路径；此时尚不能把瓶子—手腕关系宣称为已验证刚性连接。成功至少联合以下证据：

1. 夹爪实际角度、速度、估计力矩及有效夹持面合理，无异常变形或顶推。
2. 机械臂确实产生了预期方向的实际响应，请求抬升不冒充实测抬升。
3. 外部相机支持物体离桌并随手移动；透明物体深度缺失不能自动补成成功。
4. 腕部图像中目标相对夹指稳定，无明显下滑；特征匹配应区分物体和背景，单项 ORB 尺度或内点数不能独立定结论。

证据矛盾或不可观测时停在“未验证”，回支撑或补观测，不扩大抬升或进入倾倒。承载通过后才更新对应携物注册；滑移、重新抓取或显著变形使该关系失效。改变力矩、增益或抓持位置需有依据，不连续重复同样失败，也不只靠加力继续。

## 6. 温度、电量与独立监督

SDK 温度辅助判断默认是壳体 `temperature()[0] > 85℃`、绕组 `temperature()[1] > 120℃`。这是软件辅助判值，**不是已核实的固件动作门限，也不是建议持续工作温度**。夹爪自建温度检查另行说明，不能混同。

阈值上限按[任务入口第6节](#source-00)的用户指定规则执行：使用适用于本机的宇树官方最大值及其原有适用条件，不额外设置更低的自定义上限或自定义跟踪误差停机门限。历史程序的4 Nm、0.065 rad及其他自设数值仅作实验记录，不作为后续任务默认限制。

- 编译、主要规划、场景计算与恢复路线准备尽量在接管前或经实测验证的低负载姿态完成；接触后仅作必要的快速局部修正。
- 本地监督独立于聊天、大模型、SSH 和耗时子进程，持续检查反馈新鲜度、模式、温度、电量、速度、跟踪误差及竞争指令；计算期间也不能形成检查空档。
- 规划、图像处理和人工检查设置单调时钟超时。超时不仅是杀掉子进程，应转入当前状态适用的已验证恢复分支。
- “停止轨迹”可能仍保留前馈和高负载；“停发”也可能导致下垂。程序实际故障行为必须提前核实。
- 历史静态力矩转移仅在采样状态与控制项匹配时保持该点总力矩连续，不是完整重力模型。积分补偿曾增加发热，不能因重启自动重启、叠加；参数变化必须版本化并平滑验证。

历史倒水发生过约 121℃绕组软件故障，后续壳体观察到约 88℃；搬瓶也观察到约 117℃绕组。临时热卸载程序曾跳过普通温度拒绝检查，只允许白名单空臂撤回。**该版本属于事故记录，禁止作为常规任务入口或通用恢复方案。** 不重启清锁存、提高门限或默认绕过检查继续同一动作。

## 7. 异常分支与恢复原则

| 异常 | 首先保存和判断 | 下一步原则 |
|---|---|---|
| 反馈陈旧、CRC/模式异常、竞争控制 | 当前状态是否仍可信、控制器实际停发/保持行为 | 按已验证失联预案处理，必要时现场协助；无反馈不盲动 |
| 跟踪误差或位置不符 | 实际 q/dq/力矩、模式、模型、接触与图像 | 结合实际位移及任务效果区分负载静差、程序限制、通信与接触；不设置自定义跟踪误差停机门限 |
| 视觉过期、模型/目标版本变化 | 当前物体、姿态及工具是否改变 | 失效相关路线，在低负载更新；不能继续旧 ready |
| 未抓住或滑移 | 夹爪、外部离桌与腕图证据，支撑位置 | 沿适用返回路径回支撑，确认稳定后松开；重新定位再决定是否重试 |
| 温升或低电量提前预警 | 剩余动作与返回余量、可支撑位置 | 在状态可信且路径有效时优先放置/减载，不等待故障再编译 |
| 已触发故障且现有程序不能减载 | 保持力矩、物体支撑、通信和现场条件 | 明确报告必要现场协助；不能持物长期试验绕过保护 |
| 内部检查或规划超时 | 所在状态、是否持物、已验证退出分支 | 自动进入有界返回/放置/等待策略，不让伸臂依赖聊天回复 |
| 洒漏、杯移位或倾倒中断 | 载荷是否稳定、流出状态、可回正路径 | 停止增加倾角，沿检查过的回正与支撑路径处理 |

恢复从实际状态开始，不把“反向播放原路径”当作天然有效。已有异常变化、滑移或大倾角时需重新核对相关段。程序能力不足应尽量在低负载阶段修复；无法完成的恢复如实标为缺口。

## 8. 暂停、停止、结束和重新开始

- **暂停**：停止推进新阶段，按约定保持、减载或有支撑放置；明确仍运行程序与超时。暂停不自动等于停发或卸力。
- **停止控制/退出**：按用户要求和既定方案做最小必要处理，停止自己启动的程序并核验；不以“必须完成全部归位”为由拖延，也不擅自启动替代保持、站立或 AI 服务。
- **明确急停**：优先按现有已验证急停及现场流程处置，不继续原任务以求正常结束。
- 退出可采用适用的渐退或交接，但历史约 5 秒渐退只对当时悬挂条件验证过；不能作为任何现场的固定配方。停止发布不证明断电或零力矩。
- 核验实际 PID 与可执行路径、串口占用、发布活动，再被动观察。旧 PID/status 文件存在不代表程序仍在运行。
- 分别报告归位保持误差、卸力后自然姿态和最终物体状态。卸力后可能回落，下一轮重读实际姿态、模型与温度，不从旧休息目标续跑。

默认报告、选取图像和资料保存在本地；服务器只部署所需代码、二进制、配置与日志，分别说明路径。记录墙钟用于追溯，单调时钟用于超时/时长，保留设备时钟、帧号、采集/发送/接受时间的实际含义。

训练需另行确定 observation、action、坐标系、频率、延迟与标签；同时保存请求、限幅后指令、实际反馈、Kp/Kd/前馈、模式、夹爪、温度、电量、版本和干预。实测 q 不能冒充控制动作。

历史身体发布目标约 500 Hz，未证明硬实时；身体状态文件标称约 5 Hz、阶段反馈日志约 2 Hz，夹爪频率另测。关键快照及顺序采集的三相机不是同步训练轨迹。独立采集器不得阻塞控制，测实际频率、抖动、延迟与丢帧；成功、失败、恢复、调参和等待分别标注。

## 10. 整个任务的 token 用量记录

token 统计属于任务记录，使用运行环境提供的实际 usage/计数证据；不要求机器人控制程序自行计量，也不阻塞运动监督。读取不到时报告未知和缺失范围，不用额度剩余百分比、字数、字符数或经验比例估算，不折算费用。

1. **开始定范围并采样基线。** 写明本次任务包括的准备、执行、恢复、分析、文档等阶段，以及计数起止的定义、时区、采样时间、task/run ID、会话/主代理 ID、数据来源。开始后才取得基线时，标明之前阶段缺失，不能假定从零开始。
2. **按同一范围记录增量。** 若来源是累计计数，用同一会话/代理及同一计数器生命周期的结束值减开始值；若来源是逐调用 usage，按调用唯一 ID 汇总本范围内新增调用。计数器重置、分叉或不同来源不能直接相减，出现负差先核查。
3. **主代理与子代理去重。** 逐一列出纳入的会话/代理 ID、父子关系和起止；核查主计数是否已经包含子代理。已包含则不再加子计数；未包含则分别汇总。跨分叉只计分叉后新增调用，继承的历史 usage 记录不重复计算；真实新增调用再次读取上下文的 input 仍按实际 usage 计算。
4. **字段与公式固定。** 记录 `input`、`cached_input`、`output`、`reasoning_output`、`total`；`total = input + output`。缓存输入是 input 的子集，推理输出是 output 的子集，均不可再加进 total。原始来源字段名、含义或口径不同要保留并说明，不能强行混算。
5. **结束标明截点与完整性。** 写明最终采样时间、已覆盖阶段、进行中调用、尚未入账的当前回复/归档和缺失代理。部分可见时输出“已知小计＋未知范围”，不能声称整个任务精确总量。可以后续补采最终值，但不覆盖原采样证据。

建议在本次运行记录中保存下表及来源引用；无需把会话全文复制入机器人服务器或长期资料库：

| 范围 / 会话与代理 ID | 基线时间与值 | 结束采样时间与值 | 去重后的增量 | 来源与完整性 |
|---|---|---|---|---|
| 主代理及所属阶段 | 五个字段或未知 | 五个字段或未知 | 五个字段或未知 | 累计/逐调用；是否已含子代理 |
| 子代理/分叉新增范围 | 同上 | 同上 | 同上 | 调用唯一 ID、继承历史排除及缺失 |
| 任务合计 | 不混用计数器 | 标注统计截点 | total=input+output | 完整/进行中/已知小计，未知范围 |

最终结果可明确写成：“截至某采样时刻，已知 input=…、cached_input=…、output=…、reasoning_output=…、total=…；当前回复/某代理未入账，整体尚未完整。”来源未提供某个子集字段时保留未知，不能填写 0。


## 11. 2026-10-21 空载验证、模型前馈和任务预算补充

本轮一次性身体消息同时管理双臂已空载通过，不再把“旧单臂程序都发送29关节”解释为机器人不能双臂协同。统一发布器之外，还需要双夹爪监督、接触/滑移视觉、明确允许接触区和持物恢复；这些未完成时只能报告空载能力通过。

悬挂条件下腰部使用“骨盆固定模型重力差”曾使请求正向0.05 rad时实际响应很小且方向异常，并触发跟踪故障。去掉**腰部**该项后单次试验实际变化约0.0228 rad、根部俯仰变化约−0.0046 rad，返回正常。该结果说明承重边界影响前馈，不能据此加大腰部补偿或声称获得可靠世界坐标倾角。手臂模型重力差在空载小范围降低了静差，不能推广为准确持物重力模型。

本轮有限空载比例位置伺服采用实测误差反馈、关节类别总指令力矩限幅及阻尼，没有积分。联合准备运行中肩roll稳态误差仍约0.016—0.017 rad，因此目标角度到位不代表夹指准确落在瓶面。它不是接触阶段的已验证阻抗控制。

| 失败返回 | 停止增加倾角、回正、返回支撑的逐段路线；大倾角不直接跳到桌面端点 |

成功需支持水进入指定容器、量符合约定、无超限洒漏、瓶子稳定回正并按约定放置。只有倾斜、路径通过、检测到出水或杯中有水，都不足以证明定量目标完成。洒漏、落点偏移、杯移动、滑移、遮挡或超时进入恢复，不持续增大倾角探测。

### 6.1 拧开瓶盖与其他双臂扭转操作

2026-10-21拧盖任务仅完成连接、被动反馈、当前图像、瓶盖近似相机坐标定位和源模型审查，没有启动身体或夹爪控制，没有拧盖或搬放。不能把该任务记为实物拧盖成功。

**进入条件：**瓶身与瓶盖分别识别，抓持区域、轴线、尺寸与工具关系足够可信；固定瓶身的一侧已验证抗转、抗滑且不造成异常变形；另一侧具备瓶盖有效接触与受限扭转控制；双臂使用同一协调身体控制器，准备接近、夹持、旋转、重新抓取、取盖、放置和异常恢复路径。

- 抓住瓶身的承重能力不等于抗扭能力，夹住瓶盖不等于能传递开盖扭矩；电机估计力矩不直接等于瓶盖轴扭矩。
- 明确螺纹方向、封口环/卡扣状态、转动范围、轴向上升跟随或受限顺应，以及反作用力矩、横向偏载与滑移的观测方法。不能只固定末端位置并无限转腕，也不能用厂家夹力上限替代本机接触参数。
- 左右零点和开合方向分别验证。历史左右单臂控制器不能同时启动以拼成双臂系统。
- 允许接触只针对各指腹与指定瓶身/瓶盖区域，仍检查另一只手、夹爪本体/导轨/相机、瓶肩和桌面。
- 每次转动或重新夹持有角度、时间、负载和重复次数界限；瓶身意外转动/倾斜、盖上滑移、异常阻力或视觉失效即停止推进，按支撑与受力状态恢复。
- 脱盖需看到瓶盖与瓶口独立分离、瓶口打开；腕转角、位置升高或力矩下降不能独立证明螺纹已完全脱离。
- 结束分别验证水瓶独立直立、瓶盖与瓶子分离并放在桌面、夹爪松开撤离、无持续悬空物；必要时观察瓶盖是否滚动。

缺少这些能力时，先开展不依赖它们的资料、感知和离线准备；不把单次抓瓶经验外推为自动双臂拧盖能力，也不以任务监督停在高负载位置等待后续开发。

## 7. 标定与模型验证任务

区分相机内参、相机间外参、相机—身体、腕部—工具/腕相机、夹爪开度与真实几何、负载/力相关辨识。先核查厂家或已有参数与本机安装是否匹配；不必每次全部重做。

## 8. 训练数据与重复实验任务

训练目标需另行明确；已有抓取实验不表示训练完成了模型。先定 action 是关节目标、增量、末端位移还是其他量，以及 observation、坐标系、更新率、延迟和终止语义，再采集和部署。

1. 连续保存三相机/深度、全身与夹爪状态、请求/限幅/最终控制指令、Kp/Kd/前馈、模式、温度、电量、版本与人工干预；按定义补齐插值内部上下文。
2. 建立采集—发送—接受—执行—观察的时间关系，保留各时钟与帧号；实测频率、延迟、抖动、丢帧和对齐误差。
3. 历史约 500 Hz 是身体发布目标；状态文件约 5 Hz、阶段日志约 2 Hz，不是统一采集率，也不是硬实时保证。关键快照不能补成严格同步连续轨迹。
4. 固定并记录承重方式、安装、负载和控制配置；参数变更划分版本。失败、恢复、调试等待和成功分别标注，不把倒水失败整理成成功演示。
5. 采集不阻塞控制及独立监督，数据失败不得无界保持伸臂；按计划回到支撑或低负载，标记该轮无效/中断。
6. 重复性评估规定重置方法、样本数、成功/失败口径与独立测试场景；一次成功不代表泛化。训练集与评估集避免使用同一轮数据而掩盖问题。
